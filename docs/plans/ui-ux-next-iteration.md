## 1. 项目理解与调研边界

- 前台：静态 HTML + Vue 3 Options API + Bootstrap，显式加载脚本，无构建步骤。
- `index.html` / `css/style.css` 负责界面；`js/main.js` 集中管理前台交互、草稿、资源应用与结果展示。
- RunPod 请求在 `js/runpod-client.js`；收藏与历史图片由 `js/history-store.js` 持久化。
- 统一资源库客户端在 `js/catalog-client.js`；同源 FastAPI + SQLite 服务在 `catalog_service/`。
- 控制台入口 `admin.html`，交互与样式在 `js/catalog-admin.js` / `css/catalog-admin.css`。
- 已阅读 README、AGENTS、既有 UI 计划、相关前后台实现、图片服务与测试入口，并查看线上现有生图页面，确认满 30 条历史时的实际排版。
- 后台上传流程依据代码分析，未登录后台实测上传。多尺寸适配、新交互与错误恢复需要在实施时用本地数据验证。

## 3. 推荐的工作区布局

桌面默认给结果更多空间，起始比例约为左 44%、右 56%；宽屏提供可拖动分隔条、最小宽度、键盘调整与重置。比例只是起点，以 1366/1440/1920 宽度的实际阅读效果验收。

```text
生图 / 资源库                              收藏 · 设置
┌────────── 编辑区 ──────────┬────────── 工作区 ──────────┐
│ 模板选择                 ⋯ │ 结果 | 预设与片段          │
│ 正向提示词                 │ 当前请求 ▾  筛选  查看历史 │
│ 负向提示词                 │                            │
│ 尺寸、种子、常用采样参数   │          主图              │
│                            │                            │
│ 高级参数 / Workflow  ▸    │ 缩略图条                   │
│                            │ 尺寸 · Seed · 执行耗时     │
│ 草稿状态                   │ 提示词 ▸  更多详情 ▸       │
├───────────────────────────┴────────────────────────────┤
│ 生成 / 加入队列                 运行 1 · 排队 2          │
└────────────────────────────────────────────────────────┘
```

- 右侧「结果 / 预设与片段」互斥显示，消除快捷库对图片的纵向挤压。切换保留当前请求、图片位置、搜索和各面板滚动位置。
- 结果内部默认让主图占满可用宽度；历史通过紧凑选择器和「查看历史」局部面板访问，不在窄右栏永久占 1/3。
- 历史面板有明确关闭与回到图片的入口，不形成层层弹窗；打开时保留所选项与列表位置。结果放大模式可利用整个工作区宽度。
- 高度随视口调整，为底部生成条预留空间。图片使用 contain 完整展示，参数折叠不改变历史列表的滚动边界。
- 1024–1199 宽度优先确保编辑和图片最小宽度，空间不足时单列；手机保留单列与明确的结果入口。断点依据内容宽度，避免只按屏幕宽度在窄容器里强开双栏。
- 无历史时保留轻量结果占位，让工作区结构稳定。

## 4. 分阶段实施

### 第一阶段：桌面布局、历史与结果信息层级

交付：解决最明显的拥挤，建立后续交互的稳定容器。

1. 生图页改用适合工作台的弹性宽度、合理外边距与宽屏上限；资源库独立控制网格密度。
2. 实现右侧「结果 / 预设与片段」切换和历史局部面板。
3. 历史条目压成约两行：小缩略图或任务占位、时间、可辨识名称/短提示词、中文状态和张数。完整错误、Job ID、Endpoint、请求大小收进详情，提供复制。
4. 历史增加「全部 / 进行中 / 已完成 / 失败」筛选和搜索，搜索模板名与正向提示词；空筛选结果明确提供清除入口。
5. 主图下优先显示尺寸、Seed、Steps、CFG、耗时；提示词可展开和复制；低频技术字段默认折叠。失败或运行中时，就地提供错误、重试或取消。
6. 重试使用独立按钮，状态标签只传达状态；运行中记录不因筛选或折叠变得无法找到。
7. 保留最近 30 请求等现有存储边界，本轮解决展示密度，不通过扩大持久化数量掩盖问题。

主要文件：`index.html`、`css/style.css`、`js/main.js`。有行为改动时补充相应 Node 回归用例。

### 第二阶段：片段和预设可识别、可放心应用

交付：无图也能判断内容，插入位置与按钮一致。

1. 快捷条目改为「名称 + 正/负目标标识 + 2–3 行正文 + 操作」，有图时图为辅助，无图/坏图直接用文本承担识别，不占据大块空图区域。
2. 提供点击、键盘均可打开的完整文本预览和复制；鼠标悬停仅作为辅助，不作为唯一入口。预设分别展示正向、负向摘要。
3. 同步资源库卡片、快捷面板和管理弹窗的摘要层级，保留三类资源的不同语义。模板没有预览图时使用模板信息，而非无意义的大图占位。
4. 插入规则明确区分：默认「插入当前编辑框」沿用最近光标；明确「插入正向/负向」遵循指定字段，并使用该字段自己的有效光标，无记录才追加末尾。界面显示目标；插入后恢复焦点并提供就近撤销。
5. 预设整块替换前可看到正负内容和覆盖范围，保留现有撤销能力；修正“全部追加末尾”等与现有光标插入不一致的文案。
6. 搜索优先匹配名称和正文；最近使用、收藏常用片段作为后续小步增强，先完成内容可见和插入可靠性。

统一库数据分两步：

- 前端先用现有详情接口按需加载当前可见片段的内容，限制并发、缓存详情，并显示加载/失败重试；本地片段直接读取正文。不在页面初始化时无界请求全部资源，不将描述当成正文。
- 统一库规模增长时，推荐给列表增加有长度上限的正文摘要与目标字段，从**已发布快照**派生；详情仍按需获取全文。该步骤涉及冻结 API 契约，需单独更新服务、客户端、契约文档和测试，后端先兼容部署，前台保留旧服务回退。全库正文搜索若要实现，需同时明确服务能力，不能声称只靠已加载详情就能搜全库。

主要文件：`index.html`、`css/style.css`、`js/main.js`、必要时 `js/catalog-client.js`；摘要接口扩展另列独立提交。

### 第三阶段：后台拖放、构图与连续保存

交付：图片先在本地准备，看到最终效果后再保存到草稿。

交互流程：

```text
点击 / 拖入 / 在上传区粘贴图片
    → 本地预览与格式检查
    → 拖动构图、缩放、重置 / 完整显示
    → 同时查看资源卡片与快捷缩略图效果
    → 保存到草稿
    → 明确提示“尚未发布”
```

1. 上传区支持点击、拖放和区域内粘贴；拖入时高亮，多文件给出单图限制提示；阻止文件落到该区域时触发浏览器导航。
2. 采用一个明确的 16:9 成品画面，提供「完整显示」和「裁剪填满」两种方式；裁剪支持拖移和缩放、重置，并有键盘/触控可操作控件。
3. 后台预览与资源卡片采用相同比例，快捷缩略图完整显示成品图，避免再次 cover 丢失用户选好的部分。此方案先不引入每个展示位置独立的焦点元数据。
4. 用户确认后浏览器输出裁剪成品并压缩，复用现有上传接口和服务端图片检查。保留 ≤5 MiB、≤16 MP、静态 PNG/JPEG/WebP 输入及 ≤480px、≤64 KiB WebP 成品约束。
5. 放宽“选图”的时机：新建、文本有改动时仍可本地选图和调图。真正写入时按顺序保存文本草稿 → 用返回的新 `baseRev` 上传图片；界面显示具体阶段。
6. 保存链串行执行，期间防止重复提交和切换资源；异步回包校验资源身份/操作标识，避免旧响应覆盖新编辑。成功后更新必要状态并保持滚动与焦点，不每次跳回名称。
7. 文本保存成功但图片失败时，明确提示部分成功并保留本地构图，允许仅重试图片。409 时保留本地内容并提示版本冲突，不静默覆盖；登录过期时保留可重试状态。
8. 取消本地调整不更改现有图片；图片成功更新后仍需显式发布。切换条目/离开页面的未保存检测包含本地待传图片。
9. 文件原图只保留在当前编辑会话内，释放 Object URL / ImageBitmap。服务端仍不存原图；离开后若要扩大已裁掉的范围，需要重新选原图，界面说明这一实际限制。
10. 将详细压缩规则收进说明，主要文案聚焦「拖入图片 → 调整 → 保存到草稿」。

主要文件：`admin.html`、`css/catalog-admin.css`、`js/catalog-admin.js`。裁剪几何与压缩逻辑可拆成独立小模块并显式声明脚本顺序，不为本轮升级框架或引入构建器。

## 5. 验证与验收

实施时先用本地样例复现问题，不消费 RunPod 额度，不在生产创建/发布测试资源。

### 代表性场景

1. 1366、1440、1920 桌面宽度；1024 平板；390 手机与较窄 360 手机。检查浏览器缩放后、长中英文名称和极长无空格字符串。
2. 历史 0 / 1 / 30 条，混合排队、运行、成功、失败；单请求多图；长错误与长 Job ID。名称、状态不互相挤压，技术字段不撑高列表。
3. 图片分别为横图、竖图、方图；主图完整可见，生成条不遮内容，历史筛选不改变当前图片状态。
4. 片段有图 / 无图 / 坏图 / 超长文本，正向与负向交替编辑后插入；选区替换、无光标追加、撤销；统一库详情慢网、失败和旧缓存。
5. 新建后台条目时先拖图，再填文本并保存；已有条目改文本后换图；裁剪取消、重置、替换；透明图、EXIF 方向、损坏图、多文件、超限图。
6. 上传慢网、401、409、413、网络断开；文本成功但图片失败；双击保存、保存期间切换资源；失败后保留构图并可重试。
7. 后台草稿图变化时公开图不变，显式发布后才更新；本地副本继续固定来源版本。
8. 只用键盘完成选择片段、展开全文、插入、撤销和返回编辑；Tab 不落到被遮挡的背景。

### 自动化与手工验证

## 6. 交付顺序与协作

顺序：第一阶段布局/历史 → 第二阶段内容预览与插入 → 第三阶段图片编辑/保存 → 第四阶段余项。每阶段均交付可独立检查的结果，遇到实际体验问题先修正该阶段，再扩大功能。

第一步实施任务：仅围绕 `index.html`、`css/style.css`、`js/main.js` 完成弹性桌面布局、右侧切换与紧凑历史，先用 30 条样例记录和不同方向图片验收，再加入下一阶段。

主代理负责交互决策、状态设计、核心实现与浏览器验收。`opencode-go/deepseek-v4.1-flash` 可辅助定向代码核查、样例整理、边界用例和文档对账；每次限定少量文件和明确产物，最终结论由主代理复核。本次辅助调用中断，未将其视为已经完成的审查结果。

本轮无需重构 RunPod 传输、改存储上限、引入新前端框架或安装依赖。实施范围以以上可验收任务为准；两图对比、全库搜索 API、最近使用/常用收藏等增量另行小步安排。
